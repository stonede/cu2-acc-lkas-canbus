# Serial-steering research data

This directory is the canonical, shareable home for receive-only ESP32
serial-steering captures. The raw evidence is kept in Git so it can be
reviewed from another computer and reused in later analysis.

## Directory policy

- `data/` contains raw capture output and its sidecar files. Keep the JSONL
  byte-for-byte unchanged after collection.
- `figures/` contains plots or screenshots derived from the raw captures.
- `firmware/serial-steering/captures/` is local scratch space. It is ignored
  by Git and may contain smoke tests, failed attempts, or very large temporary
  files.

For one capture, keep these files together whenever they exist:

| File | Purpose |
|---|---|
| `<id>.jsonl` | Raw host capture; authoritative evidence |
| `<id>.jsonl.session.json` | Port, baud, timing, clean-shutdown and record counts |
| `<id>.jsonl.bad.log` | Host lines that could not be parsed, including useful USB/boot diagnostics |
| `<id>.jsonl.gaps.jsonl` | Host sequence-gap report generated by newer capture tools |

Do not commit only a PNG. A figure is useful for orientation, but the raw
capture and metadata are what make the result reproducible.

## Current manifest

Capture 3 and capture 4 were collected in the vehicle on 2026-08-08. The
physical-layer modules were connected to the pins marked `RX`, directly from
module RX to ESP32 input, without added resistors. The vehicle-side high-level
voltage of those RX pins was not measured separately, so the captures prove
that the path carried traffic but do not prove that the ESP32 input voltage is
electrically safe.

## Reproduce the analysis

Run the analyzer from `firmware/serial-steering` and write new figures into
`research/serial-steering/figures/`:

```powershell
Set-Location firmware\serial-steering
py -3 tools\analyze_log.py ..\..\research\serial-steering\data\4.jsonl --plot-output ..\..\research\serial-steering\figures\4_regenerated.png
```

Use a new output name while comparing results. Do not overwrite the original
figure until the analyzer change has been reviewed.

## Procedure for adding a future session

1. Before the test, choose a new session ID. Never reuse an existing ID or
   overwrite a previous capture.
2. Capture to the ignored local directory, for example:

   ```powershell
   Set-Location firmware\serial-steering
   py -3 tools\capture_serial.py COM4 captures\5.jsonl --duration 300
   ```

3. Stop the logger cleanly when possible. Keep every file produced with that
   ID: `.jsonl`, `.session.json`, `.bad.log`, and `.gaps.jsonl` if present.
4. Analyze the local capture and generate plots. During a solo driving test,
   do not use the laptop or enter markers; derive intervals afterward from
   the recorded serial data.
5. Copy the complete capture set, without editing the raw JSONL, to
   `research/serial-steering/data/`. Copy derived plots to
   `research/serial-steering/figures/`.

   ```powershell
   $id = '5'
   $source = 'firmware\serial-steering\captures'
   $data = 'research\serial-steering\data'
   $figures = 'research\serial-steering\figures'

   $sidecars = @(
       "$id.jsonl",
       "$id.jsonl.session.json",
       "$id.jsonl.bad.log",
       "$id.jsonl.gaps.jsonl"
   )
   foreach ($name in $sidecars) {
       $path = Join-Path $source $name
       if (Test-Path -LiteralPath $path -PathType Leaf) {
           Copy-Item -LiteralPath $path -Destination $data
       }
   }

   py -3 firmware\serial-steering\tools\analyze_log.py `
       "$data\$id.jsonl" --plot-output "$figures\$id.png"
   ```

6. Add a short provenance note to this README or the relevant vehicle-test
   report: date, vehicle state, firmware version, console baud, GPIO/channel
   mapping, module pin label (`RX` or `TX`), level shifting, and whether
   markers were used. Record electrical measurements separately when they are
   available.
7. Add the capture and figure to the manifest, run `git diff --check`, and
   verify the copied files with SHA-256 before committing:

   ```powershell
   Get-FileHash -Algorithm SHA256 -LiteralPath `
       research\serial-steering\data\5.jsonl
   ```

8. Review the diff for personal data, accidental secrets, or unrelated
   laptop logs. Commit the raw capture, its metadata, and the documentation
   update together. Leave the local scratch copy in place until the commit
   has been verified on another checkout.
